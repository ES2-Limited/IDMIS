# TRIMING Results Framework 2.0 — Indicator Definitions

This document details the 22 indicators defined in the provisional TRIMING Results Framework (version `2.0-provisional`). All indicator formulas, data sources, assumptions, and known legacy document discrepancies are recorded here for client review and final confirmation.

---

## Results Framework Metadata

- **Framework Name**: TRIMING Results Framework
- **Version**: `2.0-provisional`
- **Status**: Current (`is_current = true`)
- **Reporting Frequency**: Quarterly (`quarterly`)
- **Baseline Values**: Stored as `NULL` pending final baseline confirmation from the National Project Coordinating Unit (NPCU).

## Architectural Principles for Indicators

1. **Storage Decoupling**: Indicator values are stored in `me.indicator_value` with `source = 'computed'` when calculated by automated background workers, `source = 'manual'` when submitted through the review queue, and `source = 'import'` when bulk-uploaded.
2. **Missing Denominators**: Division by zero or missing baseline datasets never produce database errors or spurious zeroes. They result in `'not_available'` status, logged and displayed transparently in reporting views.
3. **Optimistic Concurrency & Audit**: All target and value updates are tracked with row versioning (`version`) and full audit logging in `core.audit_log`.
4. **Scope Isolation**: Multi-tenant visibility strictly enforces caller authority via `applyScope` across scheme, state, and national tiers.
